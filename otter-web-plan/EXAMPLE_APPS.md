# Reference Applications

## A. Otter Guestbook (MVP)
Frontend: HTML/CSS/JS. Backend: Otter HTTP handlers. SQLite persistence. Form validation, safe HTML rendering, parameterized insert/select, 404/405/400 handling. Automated end-to-end browser tests.

**Pass:** fresh checkout, documented build and launch, create/view entries, rejected invalid input, restart preserves data, no XSS or SQL injection.

## B. Otter React Dashboard
Frontend: Vite + React/TypeScript. Backend: Otter JSON API. Development proxy and production static serving, proper cache headers and 404 behavior.

**Pass:** clean install, npm build, Otter serves dist, API request works, browser refresh on nested SPA route works, no API fallback misrouting.

## C. Otter Three.js Showcase
Frontend: Vite + Three.js, animated camera and one optimized GLB scene. Backend: Otter scene JSON and static model hosting.

**Pass:** loads on desktop browser, reports meaningful fallback on no WebGL, no broken asset URLs, no console errors, documented model license and performance baseline.

## D. Otter React Three Fiber World
Frontend: React + `@react-three/fiber` with one GLB, lights, orbit control and interaction. Backend: Otter API stores per-user scene preferences; optional WebSocket presence.

**Pass:** frontend builds with pinned compatible packages, interaction works, save/reload works, tests verify server validation and permission checks, browser memory stays stable across scene remounts.

## E. Future Multiplayer Prototype (not MVP)
One room, 2–4 browser clients, server-validated room membership, basic state broadcast and reconnect. No claims of authoritative physics or anti-cheat. Produce metrics and feasibility report.

## Common README for each sample
Requirements, supported platforms, install, dev, production build, security limitations, test commands, screenshots if generated by test tooling, and expected behavior. Examples must compile/run rather than remaining pseudocode.
